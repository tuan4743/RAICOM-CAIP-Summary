## 实验 E（4类 v6 split：dataset/ 224原版, 验收同分布）— 进行中 🔄
- **验收确认**: 验收测试集更接近 dataset/ (组委会原版224); 验收类别顺序 = `['sunny','cloudy','rainy','snowy']`; 比的是 **F1 macro**
- dataset/ 全部可训练 (验收测试集是组委会独立持有, 不来自dataset/, 无泄露)
- 方案: 从 dataset/ 按 85/15 划 dataset_split (train 4252 / test 747, seed42, 硬链接)
- 关键改动: main_v6.py 新增 `--classes-override sunny,cloudy,rainy,snowy` → checkpoint 输出维度直接对齐验收 class_to_idx
- 输入: 224原图 上采样到 384 训练 (b2设计尺寸)
- 配置: `--data-dir dataset_split --classes-override sunny,cloudy,rainy,snowy --arch b2 --input-size 384 \
  --epochs 50 --bs 128 --lr 1e-3 --unfreeze-epoch 4 --warmup 2 --patience 15 --focal --ema-decay 0.9995 \
  --tta --rrc --randaugment 9 --random-erasing`，s2 GPU0，save-dir checkpoints_4cls_v6_split
- 评测脚本: `models/eval_f1.py` (自适应checkpoint类别顺序, 重排到验收顺序算F1 macro)
- 目标: F1 macro 93%+ 冲 97%; CPU 70分钟内

### v6 split 训练完成结果
- best(raw val acc)=81.12%, 但 **TTA+EMA 实际 F1 macro = 0.8422, Acc 87.68%** (747 test)
- best.pth 与 last.pth TTA 结果完全一致 (0.8422)
- 逐类 F1 (验收顺序):
  - sunny 0.9157 / cloudy 0.8829 / snowy 0.8000 / **rainy 0.7702**
- **瓶颈: rainy precision 仅 0.6526 (recall 0.9394)** → 模型过度判 rainy, 把 cloudy/sunny 误判为 rainy
- 根因: WeightedRandomSampler + Focal(gamma=2) 对少数类 rainy(380张) 过度补偿, 决策边界偏向 rainy
- 距 93% 目标差 ~9 点, 全卡在 rainy precision 上 → 下一步: 减弱少数类补偿(去 Focal 改 CE)

### 实验 E.2（v6 split + CE：去 Focal）— 完成 ❌
- 动机: E 的 rainy precision 0.6526 全因 Focal+sampler 过度补偿少数类；CE 不放大难样本梯度, 决策边界更中性
- 改动: 去掉 `--focal`（默认 nn.CrossEntropyLoss(label_smoothing=0.1)），其余设置与 E 完全一致
- 配置: `--data-dir dataset_split --classes-override sunny,cloudy,rainy,snowy --arch b2 --input-size 384 \
  --epochs 50 --bs 128 --lr 1e-3 --unfreeze-epoch 4 --warmup 2 --patience 15 --ema-decay 0.9995 \
  --tta --rrc --randaugment 9 --random-erasing --label-smoothing 0.1`，s2 GPU0，save-dir checkpoints_4cls_v6_split_ce
- 结果: best raw Acc **84.61%** (TTA), 比 Focal 的 81.12% 高 +3.5%
- **但 F1 macro = 0.8346 (比 Focal 的 0.8422 还低 0.008)** ❌ 诊断对、改法错
  - 逐类 F1: sunny 0.9225 / cloudy 0.8829 / snowy 0.8000 / rainy 0.7329
  - rainy precision **0.6211 (比 Focal 的 0.6526 更差)**, recall 0.8939
- 混淆 (行真/列预, 顺序 sunny/cloudy/rainy/snowy):
  ```
           sunny  cloudy  rainy  snowy
    sunny    268      18      3      5
   cloudy     18     279     24      6
    rainy      0       6     59      1
    snowy      1       2      9     48
  ```
- logit 分析: 预测 rainy 的 95 张中, 真cloudy 24张(rainy-prob 均值0.62), 真rainy 59张(0.82) → cloudy/rainy 边界本就模糊, 非loss偏置
- **结论修正**: 瓶颈不是 loss 函数偏置, 是 cloudy↔rainy 在 224px 低对比度数据上**本质可混淆**. 去 Focal 不解决, 只是把 rainy recall 也拉低了. 真正杠杆: 数据(增 rainy 硬负样本/cloudy 边界样本) 或 模型容量/输入分辨率, 而非 loss 调参.

## 实验 F（H100 复现 + 验证实验：官方验收集是否与 dataset/ 同分布）— 进行中 🔄

### 背景（判据核心）
当前所有方案"验收测试集与 dataset/ 同分布"是反推猜测, 从未验证. 用户提出干净判据:
**把模型在 dataset/ 上训练到极致过拟合（记样本不学规律）, 拿过拟合权重跑官方测试.**

- 官方 F1 暴跌 → 分布不同, 须重做泛化方案

同时在 H100（8卡, 比 V100 快）复现一份**正常训练的 E 对照**（224 输入、字母序、贴合官方 predict 接口）, 作为过拟合 F1 的对照基线.

### ⚠️ 启动卡 HF 超时问题（2026-06-26 首次启动）— 已定位解决
- 首次启动两个训练, main_v6.py 顶部已设 `HF_HUB_OFFLINE=1` + `TRANSFORMERS_OFFLINE=1` + `HF_ENDPOINT=hf-mirror.com`（用 setdefault）, 但 timm 1.0.26 加载时仍向 huggingface.co 发 HEAD 请求超时重试（5次）.
- **根因**: `os.environ.setdefault(...)` 不覆盖已存在的 key. conda env/profile 预置了 `HF_HUB_OFFLINE`（或时序问题）, setdefault 见 key 已存在就跳过 → 离线没真正生效.
- **实测对比**: shell 里 `export HF_HUB_OFFLINE=1 && export HF_ENDPOINT=https://hf-mirror.com` 再跑 → 离线加载正常 ✓; 只靠 main_v6 内部 setdefault → 仍联网超时 ✗.
- **解决方案**: 不改 main_v6.py（保持仓库一致）, 在**启动脚本里 export** 这两个变量:
  ```
  export HF_ENDPOINT=https://hf-mirror.com
  export HF_HUB_OFFLINE=1
  export TRANSFORMERS_OFFLINE=1
  ```
  权重已缓存完整（`~/.cache/huggingface/hub/models--timm--tf_efficientnetv2_b2.in1k/` blob+snapshot+refs/main 齐全）.
- **教训**: 像这类"卡了很久没解决"的环境问题, 先问用户再继续, 不要自己一直试.

### ⚠️ 过拟合 --patience 0 写错（2026-06-26 首次过拟合）
- 命令用了 `--patience 0` 想禁早停, 但 main_v6 里 `--patience 0` = "0 轮无改善就停", 第 1 轮后立即触发早停 → 只跑 1 epoch（Acc 55.42%）就退出, 根本没过拟合.
- **修正**: 过拟合应用大 patience 让它跑满, 如 `--patience 120`（或等于 epochs）. 重启过拟合时改用此值.

### ⚠️ 纯 torch 重写的 bug 根因 + 修复 (2026-06-26)
- 首版重写 forward 里**每个 bn 后都加了 F.silu**, 与 timm 不等价 (forward max diff 14.2, argmax 0/4).
- 根因: timm 的 `BatchNormAct2d` 把激活(SiLU)**内置在 bn 里**, 但 **block 末层 bn 的 act=Identity (不接激活)**:
  - `EdgeResidual.bn2` (act=Identity) — 末层不激活
  - `InvertedResidual.bn3` (act=Identity) — 末层不激活
  - 其余 bn1/bn2(InvertedResidual) 都接 SiLU
- 修复: EdgeResidual forward 去掉 bn2 后的 silu; InvertedResidual forward 去掉 bn3 后的 silu.
- 验证 (verify_puretorch.py): load missing/unexpected=0, **forward max abs diff = 0.000, argmax 4/4 一致** ✅
- eval_puretorch.py (纯 torch 单 crop, 无 TTA) 在 overfit test: **F1 macro 0.8371, Acc 0.8862** —— 与 eval_f1.py 关 TTA 的 0.8371 完全吻合, 精度零损失 ✅
- 教训: 重写框架结构时, 不能想当然每个 bn 都接激活, 必须逐层 dump timm 源码 (inspect.getsource) 看 `bn.act` 是 SiLU 还是 Identity.

4. 类别边界模糊 (sunny↔cloudy) — 22 张互错是低分辨率本质可混淆.
5. 随机性 — seed 抖动 ±0.001 量级.

**用户提议: 训练时动态划分数据集 (而非静态划分) 减少迁移损失.** 落地为 **5折交叉验证**: 合并全量数据 (train+test 5290 张) stratified 80/20 切 5 折, 每折 test 互斥.

**5折CV构建 (build_5fold.py):** seed 2026, hardlink, 输出 `dataset_split_av_kfold/fold{0-4}/<cls>/{train,test}/`. 每折 test ~453 cloudy / 110 rainy / 94-98 snowy / 400 sunny.

### 收官总结
- **本地静态 test (0.9592) 是乐观估计**, 真实泛化 (5折 OOB 0.9497) 距 0.95 国赛门槛临界. 官方迁移 -0.02 后 0.9375, 差 0.0125.
