# 场景四:agent工作
## 发生场景:
我使用的模型的glm-5.2,确实够劲,但是问题就是
- 它不会主动寻求用户的帮助,比如遇上分词器的报错,它会一直执行,不会让用户手动执行
- 它没有头脑风暴的能力,一些关键的点,比如换模型,验证脚本,多模型等想法都是我自己提出来它才往这个方向上面想的
- 时间观念,agent的时间观念普遍较弱,它给出的时间至少还要翻上一倍的时间,这段时间花在它修报错上
- 上下文,Claude code的上下文不能改,只能使用200K的上下文,但是我的glm是1M的,导致glm需要频繁压缩上下文,浪费大量时间
- 记录文档,如果没有记录文档,Claude code很难会记得或读取需要更新文档,需要你手动提醒
- 工作区,claude code如果你不告诉它怎么管理,它会一股脑地把所有东西全丢到一个文件夹底下.
- 幻觉,它做了一件事,给数据库开启了色彩抖动,但是,rainy这种强烈需要低对比度的标签最怕色彩抖动.
## 如何避免
- 最终要的就是记录文档,一定要让它在开始工作前写一个记录文档,这样即使上下文压缩后它也能第一时间开始工作.
- 看着它工作,如果出现一些奇奇怪怪的报错或者优化,给它说说你的想法.
- 工作区管理,你自己一定要给工作区做好管理,这样它就会照着你的格式创建文件.
- 常常与它交流,看看能不能启发它.
