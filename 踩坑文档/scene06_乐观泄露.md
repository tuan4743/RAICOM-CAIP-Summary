# 场景六:乐观泄露
## 发生场景:
我在比赛的时候犯了一个错误,比赛是比天气分类模型的F1,官方发下来一个整的数据集.我直接静态切割这个数据集成train和test,并且以这个test的验证为结果进行优化,导致了很多问题.  
- 本地 test 的乐观偏差会误导"够不够"的判断.静态 test 0.9592 让我以为"本地已超 0.95,只差迁移",但 5折 OOB 0.9497 才是真实泛化.如果当时全量训 + 官方测,会更早看到真实水平,不会在本地 0.001 量级上反复赌博.
- 官方 F1 是唯一真实信号,多测一次就多一个数据点.我全程只拿到一次官方 F1 (0.9375),却做了十几轮本地实验.这个信号配比完全倒挂——最该多拿的官方反馈拿得最少,最不可靠的本地 test 看得最勤.
- 本地 test 和官方分布不同，本地 F1 指导的优化方向可能和官方相反.我在本地 test 上把 sunny↔cloudy 压到 22 判错,但官方验收集的 sunny↔cloudy难例分布可能完全不同.本地优化到极致,对官方可能是负迁移.av3 就是典型:本地 -0.0008（噪声）,但谁知道官方是涨是跌?根本没法判断,因为本地 test 不是官方的好代理.
## 如何解决?
像这种给数据集的,一定要注意不要静态抽取.改为5折 OOB 0.9497最优.  
数据集切的不同,最后的训练结果也会不同.  
一定要记住,一定要根据真实结果进行优化,否则优化方向可能就不对.
