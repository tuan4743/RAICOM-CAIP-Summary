# 场景二:数据集边界处理
## 发生场景:
当对数据集进行混淆+置信验证时,发现模型会对这三种数据感到疑惑:  
- 1.特征不明(数据边界)  
表现为混合了两种标签的数据,例如:sunny和cloudy的混合特征:蓝天+云  
但是,这种并不是错的,首先明确一点:  
*类别标签是离散的，但特征空间是连续的*  
这些图片刚好落在了cloudy和sunny的边界上,但是,标签是死的,组委会给的标签就是cloudy那它就是cloudy,模型只能去学习它的特征,明确这个边界.  
但是问题又来了,模型一直在学习这些边界,它再加数据量也没用,就像萝卜纸巾,没有明确的分辨能力去分辨指令,它还是会犹豫.  
*有什么影响?*  
最明显的影响就是如果去补这类数据,效果反而可能更差,因为边界就在那里,置信率不变,模型猜对的概率是一样的,最终正确率可能还一样.  
- 2.遇见次数少(难例)  
表现为某些数据在样本中出现次数很少.例如,一张阳光直射的竹林,这种情况很少见,模型只见过白色的天空代表cloudy,所以它就把这种类别判成了cloudy,然而实际上是sunny.这种就数据集中少了,模型没有学会这种特征,所以再次遇到会误判.  
这种情况不属于边界,但是会和边界一起出现在混淆+置信验证中.  
## 如何处理?
处理这两类需要谨慎对待  
首先需要理解边界的概念:  
*边界是由"标签规则 + 特征分布"共同决定的*,标签决定一个固定的点,二特征分布决定了在这个基准点旁边的"密度"区域.  
重叠区的面积大小 = 难度,所以当模型遇到两个特征都有的标签时,这个重叠区就会变大.  
- 1.处理特征不明  
一句话就是,标 sunny 还是 cloudy，取决于标注者的规则,要根据标签的特征进行补数据集,否则反而会帮倒忙.  
*判断"补数据有没有用"的唯一正确方法：看 test 难例在特征空间的"邻居"是否在 train 里.*  
如果跟test中边界特征相近的特征在训练集中出现了,那么补数据集就是无效的.  
*有办法处理边界吗?,答案是没有,边界就是硬扣分项*  
*骗你的其实有,只有一种办法,混合模型,不同的模型的边界是不一样的,这是唯一解.*  
- 2.难例  
难例反而很好处理,直接补对应的数据就行了,但是要注意补完数据要再单独跑一遍验证,主要看:
    - F1是否低  
    - 置信度是否在70%-80%之间  
否则补的数据很可能是无效的
